# Why these files live in `public/`

Everything in `public/` is copied as-is to `dist/` and served from the domain
root. Several of these files are requested from a fixed path by something we do
not control: moving them into a folder breaks them silently — no error, no log,
only a feature that stops working.

| File | Who requests it | What breaks if it moves |
|---|---|---|
| `sw.js` | The browser, at the path where the old service worker was registered | Its **scope**. A service worker only controls URLs under the directory it is served from. At `/js/sw.js` it would control `/js/*` and nothing else, so browsers holding the old worker would never receive the kill-switch. Widening the scope requires a `Service-Worker-Allowed` header and GitHub Pages cannot send headers. The root is the only option. |
| `ads.txt` | Google AdSense's crawler, at `/ads.txt` | Ad verification. Mind the case: Pages is case-sensitive and the file spent a year as `Ads.txt`, so `/ads.txt` returned 404 while `/Ads.txt` returned 200. |
| `robots.txt` | Every crawler, at `/robots.txt` | Nobody reads it at another path. |
| `sitemap.xml` | Search engines, pointed at from `robots.txt` | It is referenced by absolute URL, so it could move — but there is no reason to. |
| `llms.txt` | Proposed convention for LLM crawlers, at `/llms.txt` | See the note below. |
| `CNAME` | GitHub Pages | The custom domain. If it does not reach `dist/`, the deploy loses svqtriana.com. |
| `favicon.ico` | Browsers, which try `/favicon.ico` when no `<link rel=icon>` matches | The tab icon. |

`sitemap.xml` and `llms.txt` are not static files: they are generated by
`src/pages/sitemap.xml.ts` and `src/pages/llms.txt.ts` from `src/data/`. They
are served at the root for the same reason as the others.

## The kill-switch: why `sw.js` still exists

The new site **registers no service worker**. But browsers that visited the old
site (≤ `v20260905`) have one installed that served CSS and JS cache-first for
30 days and HTML with stale-while-revalidate. If the file disappeared, those
browsers would keep serving the old site indefinitely.

`public/sw.js` is therefore a kill-switch: on activation it unregisters the
worker, deletes the `svq-triana-*` caches and reloads open tabs. It has no
`fetch` listener, so it intercepts nothing.

- **Keep it for at least 6 months after the cutover** (until ~May 2027), and
  while Cloudflare Web Analytics still shows visits from old browsers.
- After that window it can be deleted. Not before.
- Never register a service worker from the pages: `check:dist` does not
  explicitly forbid it, but the CSP and the kill-switch are designed so that no
  new one can exist.

## About `llms.txt`

Kept, with low expectations. It is a proposal
([llmstxt.org](https://llmstxt.org), late 2024) and **no major AI crawler is
known to consume it** — not OpenAI, not Anthropic, not Google. It costs a few
lines and may be useful later.

What actually determines whether an answer engine can describe the site is that
the content is in the served HTML. Most AI crawlers do not execute JavaScript:
that is why the navigation, the footer and all the data go in the HTML, and the
only JS is progressive.

## Hosting constraints worth remembering

GitHub Pages serves static files and **cannot send response headers**. Two
consequences that have already bitten:

- Headers have to come from the CDN in front. A `.htaccess` sat in the repo for
  a year defining CSP, HSTS and `X-Frame-Options`, and not one line of it
  applied: it is an Apache file and Pages does not run Apache. It was deleted on
  2026-09-05, when `infra/cloudflare/` was already applied and verified.
- Paths are **case-sensitive**, unlike a local checkout on Windows or macOS. A
  file that resolves locally can 404 in production purely because of case.

GitHub Pages serves extensionless URLs: `/nosotros` resolves to `nosotros.html`.
The site always chooses the extensionless form (canonical, `og:url`, sitemap,
nav) to avoid duplicating content. `scripts/serve-dist.mjs` reproduces that
behaviour locally.
